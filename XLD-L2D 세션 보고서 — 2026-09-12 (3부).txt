## 0. 프로젝트 정체성 (재확인)

**XLD-L2D** — macOS 네이티브 2D/2.5D VTuber 모델러

> **"완성된 일러스트 한 장 → 자동으로 VTuber 모델로 변환"**

**최상위 철학**:
> "가능한 가장 작은 단위로 정확하게 이해하고, 필요한 것만 계산하며, 원본은 최대한 보존하고, AI의 오류는 최소 영역에 격리한다."

- Live2D Cubism (수동 리깅)
- VTube Studio (얼굴추적 런타임)

## 2. 오늘 세션에서 한 일 (시간순)

### Phase 1: 찢어짐 정량 진단 (T1)
- \`diag_rig_v3.py\` 작성: flip grid, weld check, basis smoothness
- **결정적 발견**: edge mean = **4.11px** (예상 6.5px보다 훨씬 촘촘)
- v3는 yaw=±10°에서 30k+ flips → "약간 남음"이 아니라 **근본적으로 깨진 상태**

### Phase 2: 접근법 탐색 (v4~v7, 모두 실패)
- **v4 Laplacian solve** (λ=10/100/1000): 846k → 57k로 줄지만 basis range 붕괴
- **v5 depth-based basis**: 방향 맞지만 depth edge가 계단 → 262k
- **v6 image-space Gaussian** (σ=30/50/80): 41k → 17k, 느리게 감소
- **v7 Jacobi projection**: 버그 (오버슈트) + 근본적 한계

**수학적 결론**: "부드럽게 만들기" 접근의 한계. 계단을 ramp로 바꾸는 건 flip을 0으로 못 만듦.

### Phase 3: 성공 (v8 ~ v12)

**v8 (509 flips)**: σ=120 Gaussian + mesh Laplacian solve (λ=20) + Gauss-Seidel 투영
- BUDGET=0.5, R_X=100, R_Y=60
- Jacobi 오버슈트 방지 위해 평균나누기

**v9~v10 실패**: EPS 마스크 문제, per-edge 제약이 triangle flip 보장 못 함

**v11 (36 flips)**: triangle-level clamp 도입, BUDGET=0.20

**v12 (flip=0)**: bad-triangle 국소 Laplacian smoothing
- ALPHA=0.15, iter 20 수렴
- **모든 (yaw, pitch) 그리드에서 0 flips**

\`\`\`
[v12 결과]
[converged] iter 20
[end] total flips = 0
[basis_x] range=1.7711
[basis_y] range=1.8931
\`\`\`

### Phase 4: Swift 포팅

**B1 RuntimeRig.swift**: basis_x/y → offsets(yaw, pitch)
- Python vs Swift max diff 3.8e-06
- 성능 30ms (배열 할당 포함)

**B1.5 Model 계층**:
- \`XLDMesh.swift\`: vertices + triangles
- \`XLDRuntimeModel.swift\`: mesh + rig + source image
- \`XLDRuntimeModelIO.swift\`: bin reader
- **주의**: \`IO/XLDModel.swift\` (기존 문서 struct) 와 이름 충돌 → Model/에 새 struct는 \`XLDRuntimeModel\`로 명명

### Phase 5: SwiftUI 앱 + Metal 렌더러

**XLDApp 타겟 추가** (Package.swift):
- RigState.swift (ObservableObject)
- ContentView.swift (좌우 분할)
- RigCanvasView.swift → MetalRigView로 교체
- **Metal/MetalRigView.swift** (NSViewRepresentable)
- **Metal/RigRenderer.swift** (MTKViewDelegate)
- **Metal/ShaderSource.swift** (런타임 컴파일용 shader 문자열)

**Metal 파이프라인**:
- Vertex: position(2) + basis(2) + uv(2)
- Uniforms: viewport, image_size, offset(sx,sy), scale
- Fragment: texture sample + alpha 처리

**Shader 문제 → 해결**:
- SwiftPM이 .metal 자동 컴파일 안 함
- → 런타임 소스 컴파일 (\`device.makeLibrary(source:)\`)로 전환

**Alpha 문제 → 해결**:
- 원본 \`my_vtuber.png\`는 **흰 배경 불투명 PNG** (alpha 전부 255)
- Flood fill로 배경 alpha=0 처리
- \`\`\`
  [white] 2.4M px (49%)
  [cc] 2222 components
  [border] 1 label (테두리와 연결된 진짜 배경)
  [bg] 2.1M px (42.9%)
  → alpha=0: 2.1M, alpha=255: 2.8M
  \`\`\`
- **눈 하이라이트 살아남** (캐릭터 내부 흰색은 flood fill이 못 닿음)

## 5. 실패한 접근 (재시도 금지)

### Rig 관련
- ❌ Laplacian **smoothing** for rig basis (v3, 30 iter)
- ❌ Laplacian **solve** λ=1000 (basis range 붕괴)
- ❌ Depth 기반 Gaussian만 (v5, depth edge 계단)
- ❌ Jacobi projection (v7, 오버슈트)
- ❌ per-edge 제약만 (triangle flip 못 잡음)
- ❌ blend 0.5 (v10)
- ❌ EPS 마스크 없이 수치 위반 처리 (v9)

### Shader/렌더 관련
- ❌ SwiftUI Canvas로 464k tri 렌더 (느림)
- ❌ `ctx.setShouldAntialias(false)` + expansion 1.08 (seam 남음)
- ❌ 흰색 픽셀 무조건 discard (눈 하이라이트 손실)
- ❌ CG 래스터 per-tri color (화질 저하)

### 빌드 관련
- ❌ SwiftPM resources로 .metal 자동 컴파일 기대 → **런타임 소스 컴파일로**
- ❌ \`cat << 'EOF'\` heredoc zsh에서 깨짐 → **\`python3 << 'PYEOF'\` + write_text** 사용

## 9. 오늘 얻은 핵심 교훈

1. **"부드럽게 만들기" ≠ flip 제거** — 계단을 ramp로 바꾸는 건 한계. **국소 직접 clamp**가 정답.
2. **edge mean 4.11px**이 근본 문제 — 허용 basis diff = edge_len / sx_max.
3. **bad-triangle 국소 smoothing** (v12) — α=0.15, iter 20 수렴. 수학적으로 확실.
4. **SwiftPM .metal 자동 컴파일 안 됨** — 런타임 소스 컴파일 (\`makeLibrary(source:)\`).
5. **흰 배경 alpha 처리** — flood fill (테두리 연결 컴포넌트만 배경). 눈 하이라이트 보존.
6. **zsh heredoc + 괄호 → parse error** — \`python3 << 'PYEOF'\` + \`Path.write_text\`로 우회.
7. **파일 이름 충돌** (IO/XLDModel vs Model/XLDModel) → 기존 유지, 새 struct는 \`XLDRuntimeModel\`로.
